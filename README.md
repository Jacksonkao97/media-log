# MediaLog

个人向的动画 / 漫画 / 电影追踪表。没有后端、没有构建步骤、没有依赖 —— 一个 `index.html`、一个 `styles.css`、一个 `app.js`，数据存在 `data/{区域}.json` 里。

```
index.html      页面
styles.css      样式（跟随系统深色 / 浅色）
app.js          全部逻辑
drive.js        Google Drive 备份（可选，不用就不会加载任何外部脚本）
data/
  日本.json      707 条
  中国.json       77 条
  韩国.json        5 条
  欧美.json        0 条
tools/migrate.py  一次性迁移脚本（.docx → JSON）
```

## 使用

用 **Chrome 或 Edge** 打开 `index.html`（直接双击即可），点右上角 **连接文件夹**，选中本仓库的 `data/` 目录。

之后每一次新增 / 编辑 / 删除都会**直接写回对应的 `{区域}.json`**。

### 为什么要选一次文件夹？

浏览器不允许网页在你不知情的情况下读写本地磁盘 —— 否则随便打开一个网页都能翻你的文件。所以这里有两道墙：

- **读**：`file://` 打开的页面禁止 fetch 同目录的文件（浏览器会直接报 CORS 错误），所以数据没法自动加载
- **写**：必须由你亲手选一次目录，浏览器才认这是授权

也就是说，这一次点击是浏览器的硬性要求，绕不过去（除非改成跑一个本地服务器，那样就得先开终端）。

好消息是**只需要选这一次**：文件夹句柄存在 IndexedDB 里，之后新开浏览器会话最多点一下「重新连接」就恢复了，**不会再弹文件选择框**。Chrome 122+ 在授权时如果勾选「每次访问都允许」，则连这一下都省了。

Firefox / Safari 没有 File System Access API，会自动进入**只读模式**：仍可浏览、排序、筛选、导出，但编辑按钮不可用，以免让人误以为改动已经落盘。只读模式需要通过 http 打开（`python -m http.server`），因为 `file://` 下浏览器禁止 fetch 本地 JSON。

## 功能

- **区域标签页** —— 日本 / 中国 / 韩国 / 欧美，各自对应一个 JSON 文件，标签上显示条数
- **全列排序** —— 名称、进度、状态、分类、创建时间、更新时间；名称用 `zh-Hans-CN` 排序规则，所以中文按拼音排
- **进度排序**按数字大小（`第41卷` → 41），没有数字的条目**在升序和降序下都沉到最后**，不会夹在中间
- **搜索**（名称 + 备注，`Ctrl/Cmd+K` 聚焦）和**筛选**（分类 / 状态 / 观看状态，可多选）
- **新增 / 编辑弹窗** —— 名称、进度、观看状态、状态、分类、区域、链接、备注
- 在编辑弹窗里**改区域会把条目在两个 JSON 文件之间搬家**（旧文件删除、新文件写入，两个文件都会保存）
- 填了链接的条目，名称会渲染成可点击的外链

## 数据格式

`data/{区域}.json`：

```json
{
  "region": "日本",
  "version": 1,
  "updatedAt": "2026-08-25T08:36:31Z",
  "items": [
    {
      "id": "606b1262-8c2e-4e31-8af9-e946ccbafbf1",
      "name": "全知读者视角",
      "progress": "125",
      "watch": "看着",
      "status": "未完结",
      "category": "漫画",
      "url": "",
      "note": "正常更新",
      "createdAt": "2025-11-16T09:22:41Z",
      "updatedAt": "2025-11-16T09:22:41Z"
    }
  ]
}
```

| 字段 | 取值 |
| --- | --- |
| `watch` | `未看` / `看着` / `看完了` |
| `status` | `未完结` / `完结` |
| `category` | `动画` / `漫画` / `电影` |
| `progress` | 自由文本 —— `125`、`第41卷`、`剧场版`、`156分钟` 都行；排序时取其中第一个数字 |

`progress` 之所以是字符串而不是数字，是因为原始数据本来就混着「话 / 卷 / 剧场版 / 短篇」几种计数方式，强行转成数字会丢信息。

## 备份

**第一处：`data/` 目录本身。** 每次编辑都已经写进去了，所以在仓库里 `git commit data/` 就是一份带完整历史的备份：

```bash
git add data/ && git commit -m "log: 更新进度"
```

**第二处：快照导出。** 右上角 **导出备份** 会把四个区域打包成一个 `medialog-YYYYMMDD.json` 下载下来。

**第三处：Google Drive。** 右上角 **☁ Drive** 会把四个 JSON 原样上传到 Drive 里的 `MediaLog` 文件夹 —— 不打包、不转换，云端那四个文件跟 `data/` 里的完全一致，直接下载就能用。

## Google Drive 设置

### 先决条件：必须用 `http://localhost` 打开

Google 不接受 `file://` 作为 OAuth 来源，所以**只有通过 http 打开时才能同步**。在仓库目录运行：

```bash
python -m http.server 8000
```

然后访问 `http://localhost:8000`。（顺带一提，这样打开时 `data/` 会自动加载，连文件夹都不用选 —— 只有要编辑时才需要连一次。）

### 一次性配置

1. 打开 [Google Cloud Console](https://console.cloud.google.com/)，新建一个项目（名字随便，比如 `MediaLog`）
2. **APIs & Services → Library**，搜索 **Google Drive API**，点 Enable
3. **OAuth consent screen**：类型选 External，填应用名和你自己的邮箱；在 **Test users** 里把自己的 Google 账号加进去
4. **Credentials → Create credentials → OAuth client ID**
   - Application type：**Web application**
   - **Authorized JavaScript origins** 填 `http://localhost:8000`
   - 端口必须和你实际用的**完全一致**；换端口就要回来加一条
   - 这个流程不需要填 redirect URI
5. 复制生成的客户端 ID（`xxxxx.apps.googleusercontent.com`），粘贴到应用里 **☁ Drive** 弹窗的输入框

客户端 ID 存在 localStorage，只需填一次。

### 使用

- **上传到 Drive** —— 把当前四个区域写到云端。第一次会创建 `MediaLog` 文件夹，之后都是**原地更新同一个文件**（不会越传越多，Drive 自己的版本历史也能用上）
- **从 Drive 恢复** —— 反向覆盖本地 `data/`，会先弹确认框；必须先连接本地文件夹，否则恢复的数据无处可写，应用会直接拒绝

### 关于权限

申请的是 `drive.file` 范围 —— **本应用只能看到自己创建的文件**，读不到你 Drive 里的其他任何东西。代价是它也认不出你手动建的 `MediaLog` 文件夹，只会用自己创建的那个。

access token 只存在内存里，不写 localStorage，所以每个浏览器会话需要点一次登录（已授权过的话 Google 通常会静默通过）。`drive.file` 属于非敏感范围，个人自用不需要走 Google 的应用验证。

`accounts.google.com/gsi/client` 是**点了同步才按需加载**的 —— 不用 Drive 的话，这个应用不会请求任何外部资源。

## 关于迁移

`tools/migrate.py` 把原来三个 Word 文档解析成了上面的 JSON，共 **789** 条（292 动画 + 415 日漫 + 82 中韩漫，数量与原文一致）。三个 `.docx` 原件没有被改动，脚本可以重复运行。

原始行的格式是 `名字(进度) 看完了 (备注)`，脚本按下面的规则拆解 —— 都是启发式的，**建议抽查**：

- **进度**取第一个括号里的内容；非数字的描述（如 `神兵界篇-身份暴露`）会被移到备注，避免污染进度列
- **观看状态**：出现 `看着` → `看着`；出现 `看完了` → `看完了`；动画文档整本都是看过的，默认 `看完了`，漫画文档默认 `看着`
- **状态**：动画看 `无望/渺茫` → `完结`，`还有第X季/有望/出了第X季/连载` → `未完结`；漫画看 `正常更新/停更/休刊/腰斩` → `未完结`，`完结了` → `完结`
- `第一季完结了` 这种**不会**被当成整部完结（`绝世妖帝`、`神武帝尊` 靠这条规则保持 `未完结`）
- `剧场版` 的 9 条动画被归到了 **`电影`** 分类
- 原始括号里的备注（`正常更新`、`停更2年了`、`无望第二季`…）全部保留在 `note` 字段，没有丢信息

**需要你确认的两点：**

1. 从 `中国和韩国漫画.docx` 里挑出来放进 `韩国.json` 的 5 条：`被塔詛咒的獵人`、`归还者的魔法要特别`、`全知读者视角`、`我独自升级`、`学士再生`。
2. 这两条拿不准、暂时留在 `中国.json`：`从1级开始的异世界骑士`、`怎麼辦！我穿越成了最弱小野怪`。

不同意的话，在应用里打开编辑弹窗改一下「区域」就会自动搬家。

`createdAt` / `updatedAt` 用的是各自源文档的最后修改时间（动画 2025-06-28、中韩漫 2025-11-16、日漫 2026-08-25）—— 真实的录入时间无从得知，用文档时间至少是真实信息，而且按创建时间排序时新加的条目会排在最前面。
