# MediaLog

个人向的动画 / 漫画 / 电影追踪表。

> **这是 v2 分支**：用 Next.js 重写，目标是做成网站（手机也能用）、自动同步到 Google Drive、看新番资讯、有更新时推送提醒。
> 旧版（纯 HTML，直接改 `data/` 里的 JSON）还在 `main` 分支上，v2 完成后再合并过去。

## 本地运行

需要 Node.js 20 以上。

```bash
npm install
npm run dev
```

然后打开 `http://localhost:3000`。

第一次打开是空的：点右上角 **导入**，选中 `data/` 文件夹里的四个 JSON（可以一次多选）。之后数据保存在浏览器里（IndexedDB），刷新、关掉再开都还在。

也可以导入之前用 **导出备份** 下载的 `medialog-YYYYMMDD.json`。导入会覆盖同名区域，覆盖前会先确认。

想在手机、电脑之间同步？登录 Google 后会自动同步到你自己的 Google Drive，见下面「Google Drive 同步设置」。

想装到手机主屏幕上？见下面「安装到手机 / 电脑」。

在追的番出了新一集、在看的漫画出了新一话，想收到通知？见下面「更新提醒」。

想看本季新番、每天的更新时间表、热门漫画和院线电影？点左侧栏的 **发现**（手机上是顶部的 **发现**），见下面「新番 / 电影资讯」。动画和漫画不用任何设置；电影需要一个免费的 TMDB key。

## 功能

- **区域** —— 日本 / 中国 / 韩国 / 欧美；电脑上在左侧栏，手机上在顶部标签
- **观看状态标签** —— 全部 / 未看 / 看着 / 看完了，一键切换，带数量
- **进度 +1** —— 每行都有 +1 按钮，`第41卷` → `第42卷`；按错了点提示里的「撤销」
- **删除可撤销** —— 删除后几秒内可以点「撤销」恢复
- **搜索**（名称 + 备注，按 `/` 或 `Ctrl/Cmd+K` 聚焦）和**筛选**（分类 / 状态，可多选）
- **排序** —— 名称（按拼音）、进度、最近更新、最近添加、状态、分类；没有数字的进度在升序和降序下都排在最后
- **新增 / 编辑** —— 点任意一行即可编辑；改「区域」会把作品搬到另一个区域
- **手机友好** —— 底部弹出的编辑面板（可以下滑关闭）、右下角新增按钮、按钮都够大好点
- **Google Drive 同步** —— 多台设备自动同步，每天一份快照（见下文）
- **可以安装** —— 装到手机主屏幕或电脑上，像 App 一样全屏打开；没网也能看、能改，联网后自动同步
- **发现** —— 新番时间表、季度新番、热门漫画、院线电影；点一下就能加入片单（见下文）
- **更新提醒** —— 「看着」的动画出新一集、漫画柜上的漫画出新一话时，推送通知到手机 / 电脑（见下文）
- 跟随系统深色 / 浅色

## 数据格式

`data/{区域}.json`：

```json
{
  "region": "日本",
  "version": 1,
  "updatedAt": "2026-08-25T08:36:31Z",
  "items": [
    {
      "id": "606b1262-8c2e-4e31-8af9-e946ccbafbf1",
      "name": "全知读者视角",
      "progress": "125",
      "watch": "看着",
      "status": "未完结",
      "category": "漫画",
      "url": "",
      "note": "正常更新",
      "createdAt": "2025-11-16T09:22:41Z",
      "updatedAt": "2025-11-16T09:22:41Z"
    }
  ]
}
```

| 字段       | 取值                                                                          |
| ---------- | ----------------------------------------------------------------------------- |
| `watch`    | `未看` / `看着` / `看完了`                                                    |
| `status`   | `未完结` / `完结`                                                             |
| `category` | `动画` / `漫画` / `电影`                                                      |
| `progress` | 自由文本 —— `125`、`第41卷`、`剧场版`、`156分钟` 都行；排序时取其中第一个数字 |

`progress` 之所以是字符串而不是数字，是因为原始数据本来就混着「话 / 卷 / 剧场版 / 短篇」几种计数方式，强行转成数字会丢信息。

## 备份与同步

- **导出备份** 会把四个区域打包成一个 `medialog-YYYYMMDD.json` 下载下来，随时可以再导入。
- **Google Drive 同步**：登录 Google 后自动同步，Drive 里会有：

  ```
  MediaLog/
    日本.json  中国.json  韩国.json  欧美.json   ← 和 data/ 里的格式完全一样
    snapshots/
      medialog-2026-10-09.json                     ← 每天一份快照，格式和「导出备份」一样
  ```

  区域文件每次都**原地更新**（Drive 自己的版本历史能用，但只保留约 30 天），所以另外每天留一份快照，长期都在。要回到某一天：从 Drive 下载那天的快照，在应用里「导入」即可。

### 同步什么时候发生

- 打开应用时、每次修改后（约 1.5 秒后）、切回这个标签页时、联网恢复时，以及打开期间每 5 分钟一次
- 没有变化时只查一下文件列表，不会重复上传或下载
- 离线时照常编辑，联网后自动补上

### 多台设备同时改

每台设备都记得「上次同步时双方一致的版本」，所以能分清是谁改了什么（和 git 合并一个道理）：

- 两边改了**不同的作品** → 都保留
- 两边改了**同一部作品** → 以较晚的修改为准
- 一边删除、另一边没动 → 删除
- 一边删除、另一边**修改过** → 保留修改（宁可留下一条也不丢改动）

## 安装到手机 / 电脑

- **Android、电脑上的 Chrome / Edge**：点左下角的 **安装应用**（手机上在右上角 ⋯ 菜单里，叫 **安装到主屏幕**），或者用浏览器自己的「安装」按钮。
- **iPhone / iPad**：要用 **Safari** 打开，点工具栏的 **分享** → **添加到主屏幕**。⋯ 菜单里的 **安装到主屏幕** 会给出同样的步骤。

装好以后：

- **离线也能用**：打开过一次之后，没网也能打开、查看、修改；改动先存在本机，联网后自动同步。
- **新增作品快捷方式**：在主屏幕上长按图标，选「新增作品」，直接打开新增窗口。
- **从别的 App 分享**（Android）：在浏览器或其他 App 里分享一个网页，选 MediaLog，会带着标题和链接打开新增窗口。
- **更新**：发布新版本后，打开应用会提示「MediaLog 有新版本」，点 **刷新** 即可。

**注意：**

- 必须通过 **HTTPS** 访问（本机的 `localhost` 除外）才能安装和离线使用。手机用局域网地址 `http://192.168.x.x:3000` 打开时不行，要等部署到网上（比如 Vercel）之后。
- `npm run dev` 开发模式下不启用离线缓存。想在电脑上试安装和离线，用 `npm run build && npm start`。
- iPhone 上装到主屏幕的应用和 Safari **不共用数据**，第一次打开是空的：在应用里登录 Google 同步一次（或者导入备份）就回来了。

## 新番 / 电影资讯

左侧栏的 **发现**（手机上点顶部的 **发现**）有四个页面：

| 页面           | 内容                                                                    | 数据来源 |
| -------------- | ----------------------------------------------------------------------- | -------- |
| **新番时间表** | 昨天到六天后，每天哪些动画更新第几集、几点更新（按你手机 / 电脑的时区） | AniList  |
| **季度新番**   | 上一季 / 本季 / 下一季（按 1、4、7、10 月分季）开播的动画，按人气排     | AniList  |
| **热门漫画**   | 日本 / 中国 / 韩国最近最多人在看的漫画                                  | AniList  |
| **电影**       | 正在热映 / 即将上映 / 本周热门，中文片名                                | TMDB     |

- **加入片单**：点任意一部作品，会打开「新增作品」，名称、分类、区域、状态、链接都已经填好（观看状态默认「未看」），改一改再保存就行。剧场版归到「电影」，和迁移时的规则一样。
- **已经在片单里的**会显示「在片单」和观看状态，点它打开的是片单里那一条。从「发现」加的作品靠**链接**认出来，之后改名也没关系；以前手动加的只有名字完全一样（不分大小写、标点）才认得出 —— AniList 基本没有中文名，所以大多认不出来，这是正常的。
- **只看片单里的**：时间表日期旁边的开关，只显示你片单里的动画哪天更新。先从时间表把在追的番加进片单，这个开关就有用了。
- **标题**：AniList 没有正式的中文名。有人添加过中文别名的会显示中文，否则日本作品显示日文原名、韩国作品显示英文名，中国作品显示中文原名。加入片单前可以改成你习惯的名字。
- **更新频率**：服务器会缓存结果，时间表每 30 分钟、新番和漫画每小时、电影每 6 小时才真正去问一次 AniList / TMDB，所以打开多少次都不会被限流。
- **离线**：看过的页面没网时也能打开（显示上次的内容），没看过的会提示联网后再试。

### 电影：配置 TMDB（一次性，约 5 分钟）

动画和漫画（AniList）不需要任何配置。电影来自 [TMDB](https://www.themoviedb.org)，需要一个免费的 key：

1. 注册并登录 [themoviedb.org](https://www.themoviedb.org/signup)
2. 打开 **Settings → API**（[直达链接](https://www.themoviedb.org/settings/api)），按提示申请一个 API key（个人用途，填一下简单的说明即可）
3. 复制页面上的 **API Read Access Token**（很长的一串，以 `eyJ` 开头）；旁边那个 32 位的 **API Key** 也可以用
4. 在 `.env.local` 里加上：
   ```bash
   TMDB_API_KEY=   # 上一步复制的 token
   # TMDB_REGION=CN  # 可选：「正在热映 / 即将上映」按哪个国家 / 地区的上映日期（CN、TW、HK、US…）；不填则不分地区
   ```
5. 重启 `npm run dev`（`npm run build` 的话要重新构建）

没配置时「电影」页会显示怎么配置，其他页面不受影响。这个 key 只在服务器上用，不会发到浏览器。

TMDB 的使用条款要求注明来源，电影页底部已经写了；**公开上线前**还要在「关于」之类的地方放上 TMDB 的 logo（见 [TMDB 的说明](https://www.themoviedb.org/about/logos-attribution)）。

## 更新提醒

「看着」的作品有更新时，推送通知到开启了提醒的设备：

- **动画**：链接是 AniList 的（从「发现」加入的都是），新一集播出后提醒
- **漫画**：链接是漫画柜（manhuagui.com）的，出了新章节后提醒

在应用里点左侧栏的 **更新提醒**（手机上在右上角 ⋯ 菜单里），点 **开启提醒**，允许通知，再点 **发送测试通知** 确认能收到。每台设备（手机、电脑）要各自开启一次。

- **开启的那一刻不会提醒**：第一次检查只记下每部漫画现在的最新一话，之后有新的才通知，所以不会一下子收到一百多条。
- **一次更新超过 3 部**，合成一条「N 部作品有更新」。
- **点通知**：漫画打开漫画柜的那一页，动画打开 MediaLog。
- **改了片单**（加了作品、改了观看状态、改了链接），几秒后会自动告诉服务器，不用重新开启。
- **iPhone / iPad**：要先把 MediaLog 添加到主屏幕（iOS 16.4 以上），从主屏幕打开后才能开启。
- 对话框里会显示服务器**上次检查**的时间，以及读取失败的漫画（比如漫画柜挡住了服务器）。

**服务器上保存了什么**：开启提醒的设备的推送地址，以及它们「看着」的作品的名称、进度和 AniList / 漫画柜编号（用来写通知）。片单的其他内容不会上传。

### 设置（一次性）

更新提醒需要服务器做三件事：发推送（VAPID 密钥）、记住谁在追什么（存储）、定时检查（定时任务）。

**1. 生成推送密钥**，在项目目录运行：

```bash
npx web-push generate-vapid-keys
```

把输出的两行和你的邮箱填进 `.env.local`（或部署平台的环境变量）：

```bash
VAPID_PUBLIC_KEY=   # Public Key
VAPID_PRIVATE_KEY=  # Private Key
VAPID_SUBJECT=mailto:你的邮箱   # 推送服务有问题时联系你用
CRON_SECRET=        # 随便一串长随机字符，比如 openssl rand -base64 32 的输出
```

密钥生成一次就别再换：换了以后，所有设备都要重新开启提醒。

**2. 存储**

- **自己的服务器 / 电脑**（有硬盘的）：不用设置，存在项目目录的 `.data/track.json` 里（可以用 `TRACK_FILE` 换位置）。
- **Vercel 这类 serverless 平台**：没有能长期保存文件的硬盘，要用 [Upstash Redis](https://upstash.com)（免费额度足够）。在 Upstash 控制台建一个 Redis 数据库，把 **REST URL** 和 **REST Token** 填进 `UPSTASH_REDIS_REST_URL`、`UPSTASH_REDIS_REST_TOKEN`。在 Vercel 上也可以从 **Storage → Marketplace → Upstash** 一键创建，环境变量会自动填好。

**3. 定时检查**：让一个定时任务每隔一段时间访问一次：

```
https://你的域名/api/track/check
请求头：Authorization: Bearer <CRON_SECRET>
```

任选一种：

- **Upstash QStash（推荐，每 30 分钟）**：免费额度每天 1000 次，每 30 分钟一次只用 48 次。在 Upstash 控制台的 **QStash → Schedules** 新建：URL 填上面的地址，Cron 填 `*/30 * * * *`，Headers 加 `Authorization: Bearer <CRON_SECRET>`。
- **Vercel Cron**：项目根目录加一个 `vercel.json`：
  ```json
  { "crons": [{ "path": "/api/track/check", "schedule": "0 1 * * *" }] }
  ```
  Vercel 会自动带上 `CRON_SECRET`。但免费版**每天只能跑一次**（时间还会浮动一小时），所以只适合每天一次的汇总提醒。
- **自己的服务器**：crontab 里加一行，比如每 30 分钟：
  ```bash
  */30 * * * * curl -fsS -H "Authorization: Bearer 你的CRON_SECRET" https://你的域名/api/track/check
  ```

每次检查：动画查一次 AniList（问的是上次检查以后播出的集数）；漫画每部**每 6 小时**最多查一次（`TRACK_MANGA_HOURS` 可以改），每次最多查 40 秒，没查完的下次接着查。返回的 JSON 里有这次查了多少、发了几条通知。

**本地试**：推送需要 service worker，`npm run dev` 不行，要 `npm run build && npm start`（`localhost` 可以，局域网的 `http://` 地址不行）。开启提醒后，手动访问一次检查地址：

```bash
curl -H "Authorization: Bearer 你的CRON_SECRET" http://localhost:3000/api/track/check
```

**如果漫画一直「读取失败」**：可能是漫画柜挡住了服务器所在地区的访问。可以试试把 `MANHUAGUI_ORIGIN` 设成 `https://tw.manhuagui.com`。

## Google Drive 同步设置

一次性的，大约 10 分钟。如果旧版 v1 用过 Drive 备份，**用同一个 Google Cloud 项目**最省事 —— 应用能找到 v1 建的 `MediaLog` 文件夹，第一次同步时会把里面的数据合并进来。

1. 打开 [Google Cloud Console](https://console.cloud.google.com/)，选中（或新建）项目
2. **APIs & Services → Library**，搜索 **Google Drive API**，点 Enable
3. **Google Auth Platform**（旧名 OAuth consent screen）：
   - 用户类型选 **External**，填应用名和你的邮箱
   - **Audience → Test users** 里加上你自己的 Google 账号
   - **Data access** 里加上 `.../auth/drive.file` 这个权限（非敏感权限，只能访问本应用自己建的文件）
4. **Clients（Credentials）→ Create OAuth client**：
   - Application type 选 **Web application**
   - **Authorized redirect URIs** 加上 `http://localhost:3000/api/auth/callback/google`
     （以后部署到网上，再加一条 `https://你的域名/api/auth/callback/google`）
   - 创建后复制 **Client ID** 和 **Client secret**
5. 在项目根目录把 `.env.example` 复制成 `.env.local`，填好：
   ```bash
   AUTH_SECRET=        # 随便一串长随机字符，比如 openssl rand -base64 32 的输出
   AUTH_GOOGLE_ID=     # Client ID
   AUTH_GOOGLE_SECRET= # Client secret
   ```
   `.env.local` 不会被提交到 git。
6. `npm run dev`，打开 `http://localhost:3000`，点左下角 **登录 Google 同步**

**注意：**

- 应用在 Google 那边处于「测试」状态时，**登录每 7 天会失效一次**（Google 的规定），应用会提示「重新登录」，点一下就好。在 Google Auth Platform 里把应用**发布（Publish app）**就没有这个限制；只用 `drive.file` 这种非敏感权限，个人使用通常不需要 Google 审核。
- 登录时 Google 会列出权限，**要勾选 Google Drive 那一项**，否则无法同步（应用会提示重新登录）。
- 用 `npm run build && npm start` 在本机跑生产版本、或者自己架服务器时，还要加 `AUTH_TRUST_HOST=true`。部署到 Vercel 不需要。
- 改了这几个环境变量后要重新 `npm run build`（`npm run dev` 不用）。

## 关于迁移

`tools/migrate.py` 把原来三个 Word 文档解析成了上面的 JSON，共 **789** 条（292 动画 + 415 日漫 + 82 中韩漫，数量与原文一致）。三个 `.docx` 原件没有被改动，脚本可以重复运行。

原始行的格式是 `名字(进度) 看完了 (备注)`，脚本按下面的规则拆解 —— 都是启发式的，**建议抽查**：

- **进度**取第一个括号里的内容；非数字的描述（如 `神兵界篇-身份暴露`）会被移到备注，避免污染进度列
- **观看状态**：出现 `看着` → `看着`；出现 `看完了` → `看完了`；动画文档整本都是看过的，默认 `看完了`，漫画文档默认 `看着`
- **状态**：动画看 `无望/渺茫` → `完结`，`还有第X季/有望/出了第X季/连载` → `未完结`；漫画看 `正常更新/停更/休刊/腰斩` → `未完结`，`完结了` → `完结`
- `第一季完结了` 这种**不会**被当成整部完结（`绝世妖帝`、`神武帝尊` 靠这条规则保持 `未完结`）
- `剧场版` 的 9 条动画被归到了 **`电影`** 分类
- 原始括号里的备注（`正常更新`、`停更2年了`、`无望第二季`…）全部保留在 `note` 字段，没有丢信息

**需要你确认的两点：**

1. 从 `中国和韩国漫画.docx` 里挑出来放进 `韩国.json` 的 5 条：`被塔詛咒的獵人`、`归还者的魔法要特别`、`全知读者视角`、`我独自升级`、`学士再生`。
2. 这两条拿不准、暂时留在 `中国.json`：`从1级开始的异世界骑士`、`怎麼辦！我穿越成了最弱小野怪`。

不同意的话，在应用里打开编辑弹窗改一下「区域」就会自动搬家。

`createdAt` / `updatedAt` 用的是各自源文档的最后修改时间（动画 2025-06-28、中韩漫 2025-11-16、日漫 2026-08-25）—— 真实的录入时间无从得知，用文档时间至少是真实信息，而且按创建时间排序时新加的条目会排在最前面。
